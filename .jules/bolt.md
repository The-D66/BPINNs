## 2024-05-30 - Optimizing math aggregation over lists of tensors in custom parameter objects
**Learning:** In highly customized parameter management classes (like `Theta` which wraps neural net weights), standardizing aggregation functions via Python `sum` paired with standard `tf.norm`/`np.prod` can become a huge performance bottleneck. `sum(tf.norm(t)**2)` calculates the square root before immediately squaring again and adds sequentially, whereas `tf.add_n([tf.reduce_sum(tf.square(t))])` groups operations in the graph perfectly and avoids unstable zero-gradients, yielding a ~3-4x speedup. Furthermore, Python's built-in `math.prod` is up to 10x faster than `np.prod` for small integer tuples (like tensor shapes), skipping heavy NumPy type conversion.
**Action:** When working on parameter aggregation logic in TF models, always prefer `tf.add_n` and `tf.reduce_sum(tf.square())` over Python's `sum()` with `tf.norm()**2`. For simple python sequences like tensor shapes, prefer Python's `math.prod` instead of `np.prod`.
