## 2026-05-27 - [Optimize Tensor Value Property Computations]
**Learning:** In highly mathematical algorithms that frequently evaluate properties across a list of tensors (e.g., the total sum of squared parameters or total parameter count), Python iteration tools combined with non-optimal math operations create significant bottlenecks. Specifically, `sum([tf.norm(t)**2 ...])` is significantly slower than `tf.add_n([tf.reduce_sum(tf.square(t)) ...])`. Furthermore, using `np.prod` to calculate simple products of small tuples like tensor shapes adds considerable NumPy overhead when compared to Python's built-in `math.prod`.
**Action:** When accumulating values across a list of tensors, avoid the built-in `sum()` function and replace it with `tf.add_n()`. Prefer `tf.reduce_sum(tf.square(t))` over calculating `tf.norm(t)**2` for sum-of-squares computations to avoid unnecessary mathematical overhead. Additionally, use `math.prod` instead of `np.prod` for small integer product operations like calculating shape sizes. When implementing `tf.add_n()` on dynamic lists, explicitly check for empty lists and provide a compatible fallback (e.g., `tf.constant(0.0, dtype=tf.float32)`) to avoid exceptions.
